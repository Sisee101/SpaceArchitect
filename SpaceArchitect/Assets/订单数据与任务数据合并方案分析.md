# 订单数据与任务数据合并方案分析

本文档分析如何将TaskData与现有的SphereOrderDataConfig合并，实现"每个订单对应一个任务"的设计。

---

## 📋 当前数据结构分析

### SphereOrderDataConfig（现有）

**结构**：
```csharp
public class SphereOrderInfo
{
    public string sphereName;        // Sphere名称
    public Sprite orderImage;         // 订单图片
    public string targetSceneName;    // 目标场景名称
}
```

**用途**：
- 存储订单信息（图片、目标场景）
- 用于显示订单面板
- 通过Sphere名称查找订单信息

---

### TaskData（之前设计的）

**结构**：
```csharp
public class TaskData
{
    public int taskId;                    // 任务ID
    public string taskName;               // 任务名称
    public string description;            // 任务描述
    public string associatedSphereName;   // 关联的Sphere名称
    public bool isCompleted = false;      // 是否已完成（运行时状态）
}
```

**用途**：
- 存储任务信息
- 管理任务完成状态
- 关联Sphere和任务

---

## ✅ 合并可行性分析

### 可以合并的原因

1. **一对一关系**：每个订单对应一个任务
2. **共享Sphere名称**：两者都通过Sphere名称关联
3. **数据互补**：
   - 订单数据：图片、目标场景（静态数据）
   - 任务数据：任务ID、名称、描述、完成状态（静态+运行时数据）

### 合并的优势

1. ✅ **数据统一**：一个数据源，避免重复配置
2. ✅ **维护简单**：只需维护一个ScriptableObject
3. ✅ **关联清晰**：订单和任务天然关联
4. ✅ **扩展方便**：后续添加新字段更容易

---

## 🎯 合并方案设计

### 方案A：扩展SphereOrderInfo（推荐）

**思路**：在现有的`SphereOrderInfo`中添加任务相关字段

**修改后的结构**：
```csharp
[System.Serializable]
public class SphereOrderInfo
{
    [Header("Sphere信息")]
    public string sphereName;        // Sphere名称
    
    [Header("订单信息")]
    public Sprite orderImage;        // 订单图片
    public string targetSceneName;   // 目标场景名称
    
    [Header("任务信息")]
    [Tooltip("任务ID（唯一标识，用于任务完成检测）")]
    public int taskId;               // 任务ID（新增）
    
    [Tooltip("任务名称（可选，用于显示）")]
    public string taskName;          // 任务名称（新增，可选）
    
    [Tooltip("任务描述（可选）")]
    [TextArea(3, 5)]
    public string taskDescription;   // 任务描述（新增，可选）
}
```

**运行时状态管理**：
- `isCompleted`不应该存在ScriptableObject中（ScriptableObject是资源，不应该存储运行时状态）
- 在`TaskManager`中用`Dictionary<int, bool>`管理任务完成状态

**优点**：
- ✅ 最小改动，只需扩展现有结构
- ✅ 保持向后兼容（新字段可选）
- ✅ 数据集中管理

**缺点**：
- ⚠️ 如果订单和任务不是一一对应，会有问题（但用户说是一一对应，所以没问题）

---

### 方案B：创建新的合并数据结构（不推荐）

**思路**：创建新的ScriptableObject，包含订单和任务的所有字段

**缺点**：
- ❌ 需要迁移现有数据
- ❌ 需要修改所有使用SphereOrderDataConfig的代码
- ❌ 增加维护成本

## 📐 详细实现方案（方案A）

### 步骤1：扩展SphereOrderInfo类

**修改文件**：`Assets/Scripts/UI/SphereOrderDataConfig.cs`

**添加字段**：
```csharp
[Header("任务信息")]
[Tooltip("任务ID（唯一标识，用于任务完成检测）")]
public int taskId = -1;  // 默认-1表示未配置

[Tooltip("任务名称（可选，用于显示）")]
public string taskName = "";

[Tooltip("任务描述（可选）")]
[TextArea(3, 5)]

```

**注意事项**：
- `taskId`默认值为-1，表示未配置任务
- `taskName`和`taskDescription`可以为空（可选字段）
- 保持向后兼容：现有代码不依赖这些字段也能正常工作

---

### 步骤2：添加任务相关查询方法

**在SphereOrderDataConfig中添加**：
```csharp
/// <summary>
/// 根据任务ID获取订单信息
/// </summary>
/// <param name="taskId">任务ID</param>
/// <returns>找到的订单信息，如果不存在返回null</returns>
public SphereOrderInfo GetOrderInfoByTaskId(int taskId)
{
    if (orderDataList == null || orderDataList.Count == 0)
    {
        return null;
    }
    
    foreach (var info in orderDataList)
    {
        if (info != null && info.taskId == taskId)
        {
            return info;
        }
    }
    
    return null;
}

/// <summary>
/// 获取所有已配置任务的订单信息
/// </summary>
/// <returns>任务ID大于等于0的订单信息列表</returns>
public List<SphereOrderInfo> GetAllTaskOrders()
{
    List<SphereOrderInfo> tasks = new List<SphereOrderInfo>();
    
    if (orderDataList == null || orderDataList.Count == 0)
    {
        return tasks;
    }
    
    foreach (var info in orderDataList)
    {
        if (info != null && info.taskId >= 0)
        {
            tasks.Add(info);
        }
    }
    
    return tasks;
}
```

### 步骤3：修改TaskManager使用合并后的数据

**TaskManager修改**：
```csharp
[Header("任务数据配置")]
[SerializeField] private SphereOrderDataConfig orderDataConfig; // 使用合并后的数据配置

// 运行时任务完成状态（不存储在ScriptableObject中）
private Dictionary<int, bool> taskCompletionStatus = new Dictionary<int, bool>();

void Start()
{
    // 初始化所有任务的完成状态为false
    if (orderDataConfig != null)
    {
        var allTasks = orderDataConfig.GetAllTaskOrders();
        foreach (var task in allTasks)
        {
            taskCompletionStatus[task.taskId] = false;
        }
    }
}

/// <summary>
/// 完成任务
/// </summary>
public void CompleteTask(int taskId)
{
    if (taskCompletionStatus.ContainsKey(taskId))
    {
        taskCompletionStatus[taskId] = true;
        OnTaskCompleted?.Invoke(taskId);
    }
}

/// <summary>
/// 检查任务是否完成
/// </summary>
public bool IsTaskCompleted(int taskId)
{
    return taskCompletionStatus.ContainsKey(taskId) && taskCompletionStatus[taskId];
}

/// <summary>
/// 根据任务ID获取关联的Sphere名称
/// </summary>
public string GetSphereNameByTaskId(int taskId)
{
    var orderInfo = orderDataConfig?.GetOrderInfoByTaskId(taskId);
    return orderInfo?.sphereName;
}
```

### 步骤4：修改TaskCompletionHandler

**使用合并后的数据**：
```csharp
[Header("引用")]
[SerializeField] private TaskManager taskManager;
[SerializeField] private SphereIconManager iconManager;
[SerializeField] private VictoryVideoPlayer videoPlayer;

void OnTaskCompleted(int taskId)
{
    // 通过TaskManager获取Sphere名称
    string sphereName = taskManager.GetSphereNameByTaskId(taskId);
    
    if (string.IsNullOrEmpty(sphereName))
    {
        Debug.LogWarning($"TaskCompletionHandler: 任务 {taskId} 没有关联的Sphere！");
        return;
    }
    
    // 播放气泡消失动画
    iconManager.HideIconForSphere(sphereName, () => {
        // 动画完成回调
        StartCoroutine(PlayVictoryVideoAfterDelay());
    });
}
```

## 🔄 数据迁移考虑

### 现有数据兼容性

**现有SphereOrderDataConfig资源**：
- 现有的订单数据没有`taskId`字段
- 需要手动添加`taskId`到每个订单

**迁移步骤**：
1. 打开现有的`SphereOrderDataConfig`资源
2. 为每个订单手动添加`taskId`（从0开始，或自定义）
3. 可选：添加`taskName`和`taskDescription`

**注意事项**：
- `taskId`必须唯一
- 建议从0开始递增：0, 1, 2, 3...
- 如果某个订单不需要任务功能，`taskId`设为-1即可

## ⚠️ 注意事项

### 1. taskId的唯一性
- **问题**：如果多个订单有相同的`taskId`，会导致冲突
- **解决**：在`ValidateData()`方法中添加`taskId`唯一性检查

### 2. 可选字段的处理
- **问题**：`taskName`和`taskDescription`可以为空
- **解决**：代码中需要检查字段是否为空，提供默认值

### 3. 向后兼容性
- **问题**：现有代码可能不依赖任务字段
- **解决**：新字段都有默认值，现有代码不受影响

### 4. 运行时状态
- **问题**：`isCompleted`不应该存在ScriptableObject中
- **解决**：在`TaskManager`中用`Dictionary`管理运行时状态
