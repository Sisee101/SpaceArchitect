# 预测系统彻底修复方案

## 一、当前发现的问题

### 1.1 时间步长不一致（已修复）

**问题**：日志显示预测时间步长是 0.01 秒，但实际游戏是 0.02 秒

**修复**：
- 在 `PredictFullTrajectory` 中强制使用 0.02 秒
- 在 `StartPredictionLogging` 中强制使用 0.02 秒并记录警告

### 1.2 CoreDeflector 激活时机差异

**实际**：
- 第46帧，距离 8.26 时激活
- velChange: 0.604, accel: 30.214

**预测**：
- 第105步，距离 10.50 时激活（太早！）
- velChange: 0.848, accel: 42.394（太大！）

**问题**：
- trigger 半径计算不准确（10.56 vs 实际 8.26）
- 安全边距 50% 太大

### 1.3 位置和速度累积误差

从初始到激活：
- **实际**：位置 (-27.478, -0.498)，速度 (14.737, 1.297)
- **预测**：位置 (-29.752, -0.661)，速度 (15.331, 1.283)

**差异**：
- 位置偏差约 2.3 单位
- 速度偏差约 0.6 单位

## 二、修复方案

### 2.1 立即修复：时间步长（已完成）

✅ 强制使用 0.02 秒

### 2.2 修复 trigger 半径计算

**当前**：安全边距 50%（太大）

**修复**：
1. 减小安全边距到 10-15%
2. 或者根据实际日志调整（实际激活距离 8.26，计算半径约 7.04，差距约 17%）

### 2.3 简化 CoreDeflector 应用逻辑

**当前问题**：逻辑太复杂，可能有 bug

**修复**：
1. 简化 trigger 检测（只使用距离检测，去掉 AABB）
2. 简化应用逻辑（去掉复杂的延迟机制，进入后立即应用）

### 2.4 验证积分方法

**当前**：LeapFrog 积分

**需要确认**：
- GravityEngine 实际使用的积分方法
- 每一步的更新顺序

## 三、建议的修复顺序

1. ✅ **时间步长**（已完成）
2. **trigger 半径**（减小安全边距）
3. **简化 CoreDeflector 逻辑**（去掉复杂延迟）
4. **验证积分方法**（确保与实际一致）

## 四、如果还是不行

**考虑**：
1. 完全重写预测逻辑，从最简单的版本开始
2. 或者使用 GravityEngine 的内置预测系统（虽然不支持自定义组件，但至少基础预测是准确的）
