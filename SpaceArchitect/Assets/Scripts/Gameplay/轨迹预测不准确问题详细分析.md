# 轨迹预测不准确问题详细分析

## 一、从飞行日志发现的关键问题

### 问题1：CoreDeflector 触发时机与实际速度变化不一致 ⚠️ 严重

**日志观察：**
- **第47帧**：速度突然变化 `vel=(14.866,1.841,0.000)`，但**没有** CoreDeflector 记录
- **第48-52帧**：速度继续变化，仍然**没有** CoreDeflector 记录
- **第53帧**：才开始记录 `Core[GravityCore]:dist=6.83,grav=10.734,guidance=0.20`

**问题分析：**
1. **Core 的 NBody 引力**在第47帧开始显著影响飞船（速度从15.224降到14.866）
2. **CoreDeflector 的 trigger**在第53帧才检测到飞船进入范围
3. 这说明**Unity 的 OnTriggerEnter/OnTriggerStay 检测有延迟**，或者**trigger 范围设置较小**

**预测代码的问题：**
```csharp
// 当前代码：使用距离检测
float triggerRadius = Mathf.Max(source.triggerBounds.size.x, source.triggerBounds.size.y, source.triggerBounds.size.z) * 0.5f;
bool inTrigger = distToCore <= triggerRadius;
```

**可能的问题：**
- trigger 的实际范围可能**小于** bounds 的 size
- Unity 的 Collider 可能是**圆形**，但代码使用的是**AABB 近似**
- trigger 可能有**旋转**，但代码没有考虑

### 问题2：Core 的 NBody 引力在预测中可能被重复计算 ⚠️ 严重

**日志观察：**
- 第1-46帧：只有 `gravAcc`（GravityEngine 的引力加速度）
- 第47帧开始：`gravAcc` 显著增大（从2.767跳到2.938）
- 第53帧开始：同时有 `gravAcc` 和 `Core[GravityCore]` 记录

**问题分析：**
1. **Core 的 NBody 引力**通过 GravityEngine 计算（gravAcc）
2. **CoreDeflector 的引力**是**叠加**在 GravityEngine 结果上的
3. 但预测代码可能**没有正确区分**这两个引力源

**预测代码的问题：**
```csharp
// 在 CalculateGravityAcceleration 中：
// 可能同时计算了 Core 的 NBody 引力和 CoreDeflector 的引力
// 导致引力被重复计算
```

### 问题3：physicsUpdateInterval 的应用时机不一致 ⚠️ 中等

**日志观察：**
- CoreDeflector 在第53帧开始生效
- 但 `physicsUpdateInterval = 0.02` 秒，应该每帧都应用（因为 fixedDeltaTime = 0.02）

**问题分析：**
- 实际游戏中，CoreDeflector 使用 `Time.unscaledTime` 检查间隔
- 预测代码使用**步数计数器**检查间隔
- 如果步数计算不准确，可能导致应用时机不一致

### 问题4：速度缩放的应用频率可能不一致 ⚠️ 中等

**日志观察：**
- `speedMultiplier=1.0010` 每帧都显示
- 但实际游戏中，ShipState 在 FixedUpdate 中应用
- 预测代码中，速度缩放也在 FixedUpdate 间隔时应用

**可能的问题：**
- 如果 `fixedUpdateInterval` 计算不准确，可能导致速度缩放的应用频率不一致

## 二、关键发现：预测和实际游戏的差异

### 差异1：CoreDeflector 触发检测时机

**实际游戏：**
- Unity 的 `OnTriggerEnter` 在**物理更新之后**调用
- 飞船可能已经**进入 trigger 范围**，但 trigger 事件还没触发
- 这导致 CoreDeflector 效果**延迟应用**

**预测代码：**
- 使用**距离检测**，立即判断是否在 trigger 范围内
- 这导致预测中 CoreDeflector 效果**提前应用**

### 差异2：Core 的 NBody 引力和 CoreDeflector 引力的关系

**实际游戏：**
- Core 的 NBody 引力通过 GravityEngine 计算（在 FixedUpdate 中）
- CoreDeflector 的引力**叠加**在 GravityEngine 结果上（也在 FixedUpdate 中）
- 所以总引力 = Core NBody 引力 + CoreDeflector 引力

**预测代码：**
- 可能**同时计算**了 Core 的 NBody 引力和 CoreDeflector 的引力
- 或者**没有正确叠加**，导致引力计算不准确

## 三、解决方案

### 方案1：修复 CoreDeflector 触发检测（最重要）✅

**问题：** 预测中使用距离检测，但实际游戏使用 Unity Trigger 事件

**解决方案：** 在预测中，**延迟应用** CoreDeflector 效果，模拟 Unity Trigger 的延迟

```csharp
// 在预测中：
// 1. 检测飞船是否在 trigger 范围内
// 2. 如果进入范围，标记为"已进入"，但**不立即应用**
// 3. 在下一个 FixedUpdate 步骤中才应用效果
// 这样可以模拟 Unity Trigger 的延迟

private Dictionary<int, bool> deflectorEntered = new Dictionary<int, bool>();

// 在预测循环中：
if (inTrigger && !deflectorEntered.ContainsKey(idx))
{
    // 标记为已进入，但不在当前步骤应用
    deflectorEntered[idx] = true;
    // 在下一个 FixedUpdate 步骤中应用
}
else if (deflectorEntered.ContainsKey(idx) && deflectorEntered[idx])
{
    // 应用效果
    currentVel = ApplyCoreDeflector(...);
}
```

### 方案2：确保 Core 的 NBody 引力和 CoreDeflector 引力正确叠加 ✅

**问题：** 预测中可能重复计算或没有正确叠加

**解决方案：** 明确区分 Core 的 NBody 引力和 CoreDeflector 的引力

```csharp
// 在预测中：
// 1. 先计算所有 NBody 的引力（包括 Core 的 NBody 引力）
Vector3 gravityAcc = CalculateGravityAcceleration(currentPos);

// 2. 然后叠加 CoreDeflector 的引力（如果飞船在 trigger 范围内）
if (inTrigger)
{
    Vector3 coreDeflectorAcc = CalculateCoreDeflectorAcceleration(...);
    gravityAcc += coreDeflectorAcc; // 叠加
}
```

### 方案3：使用更准确的 trigger 范围检测 ✅

**问题：** 当前使用 bounds.size 的最大值作为半径，可能不准确

**解决方案：** 使用实际的 Collider 类型和参数

```csharp
// 在缓存时，记录 Collider 的类型和参数
public struct ColliderInfo
{
    public ColliderType type; // Sphere, Box, Capsule
    public float radius; // 对于 Sphere
    public Vector3 size; // 对于 Box
    public Vector3 center;
}

// 在检测时，根据类型使用不同的检测方法
bool IsInTriggerRange(Vector3 pos, ColliderInfo info)
{
    switch (info.type)
    {
        case ColliderType.Sphere:
            return Vector3.Distance(pos, info.center) <= info.radius;
        case ColliderType.Box:
            return IsInAABB(pos, info.center, info.size);
        // ...
    }
}
```

## 四、推荐的修复优先级

1. **最高优先级：修复 CoreDeflector 触发检测**
   - 延迟应用效果，模拟 Unity Trigger 的延迟
   - 这会导致最大的预测误差

2. **高优先级：确保引力正确叠加**
   - 明确区分 Core 的 NBody 引力和 CoreDeflector 的引力
   - 确保叠加顺序正确

3. **中优先级：使用更准确的 trigger 范围检测**
   - 根据 Collider 类型使用不同的检测方法
   - 考虑 Collider 的旋转和缩放

4. **低优先级：添加详细的调试日志**
   - 帮助定位问题
   - 验证修复效果
