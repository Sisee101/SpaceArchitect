# 预测系统彻底重构说明

## 一、修复的三个致命错误

### 1.1 致命错误1：加速度叠加与 dt 的关系

**问题**：
- 使用 LeapFrog 积分，与 CoreDeflector 的覆盖逻辑冲突
- LeapFrog 的"半步速度"与 FixedUpdate 中的速度覆盖操作不一致

**修复**：
- ✅ **改用半隐式欧拉法**：`v1 = v0 + a * dt, r1 = r0 + v1 * dt`
- ✅ 先计算加速度，更新速度，然后更新位置
- ✅ 确保与 Unity FixedUpdate 的执行顺序完全一致

### 1.2 致命错误2：Trigger 检测的滞后性与范围不一致

**问题**：
- Unity 的 trigger 检测基于 Rigidbody 边缘，而不是中心点
- 只检测飞船中心点，导致激活时机延迟

**修复**：
- ✅ **增加飞船半径补偿**：在 `Start()` 中从 Collider 获取飞船半径
- ✅ **triggerRadius 包含飞船半径**：`triggerRadius = actualTriggerRadius + shipRadius`
- ✅ 确保预测中激活时机与实际游戏一致

### 1.3 致命错误3：LeapFrog 积分与覆盖逻辑的冲突

**问题**：
- LeapFrog 积分在中间步骤插入 CoreDeflector 逻辑，导致物理计算不一致
- 速度更新的时机与实际游戏不匹配

**修复**：
- ✅ **改用半隐式欧拉法**，完全避免 LeapFrog 的中间步骤问题
- ✅ **修正积分顺序**：
  1. GravityEngine 计算加速度并更新速度
  2. CoreDeflector 叠加效果
  3. ShipState（速度缩放已移除）
  4. 更新位置
  5. Update 阶段的 Lerp（Capture/Hub）

## 二、关键修复细节

### 2.1 积分方法改变

**之前（LeapFrog）**：
```csharp
// 步骤1：v += a * 0.5 * dt
currentVel += totalGravityAcc * (dt * 0.5f);
// 步骤2：r += v * dt
currentPos += currentVel * dt;
// 步骤3：重新计算新位置的加速度
Vector3 newGravityAcc = CalculateGravityAt(currentPos);
// 步骤4：v += a * 0.5 * dt
currentVel += newGravityAcc * (dt * 0.5f);
// 问题：在步骤2和步骤4之间插入 CoreDeflector，导致物理不一致
```

**现在（半隐式欧拉法）**：
```csharp
// 步骤1：计算当前加速度
Vector3 gravityAcc = CalculateGravityAt(currentPos);
// 步骤2：更新速度
currentVel += gravityAcc * dt;
// 步骤3：CoreDeflector 叠加效果（基于更新后的速度）
currentVel = ApplyCoreDeflector(currentPos, currentVel, ...);
// 步骤4：更新位置
currentPos += currentVel * dt;
```

### 2.2 Trigger 检测修复

**之前**：
```csharp
// 只检测中心点
float distToCore = Vector3.Distance(currentPos, corePosition);
bool inTrigger = distToCore <= triggerRadius;
```

**现在**：
```csharp
// 在 CacheGravitySources 中：
snapshot.deflector.triggerRadius = actualTriggerRadius + shipRadius;

// 在预测中：
// triggerRadius 已经包含了飞船半径补偿
bool inTrigger = distToCore <= triggerRadius;
```

### 2.3 CoreDeflector 公式修复

**严格按照实际代码公式**：
```csharp
// 1. 基础引力
Vector3 radialGravity = -radialDirection * (coreEffectiveMass / (dist * dist));

// 2. 引导加速度
Vector3 idealTangentialVel = tangentDir * vel.magnitude;
Vector3 velocityToTangential = idealTangentialVel - vel;
Vector3 guidanceAcc = velocityToTangential * guidanceStrength / dt;

// 3. 轨道半径修正（如果有）
if (targetOrbitRadius > 0f)
{
    float radiusError = dist - targetOrbitRadius;
    guidanceAcc += -radialDirection * radiusError * guidanceStrength * 0.5f;
}

// 4. 混合加速度
Vector3 totalAcc = radialGravity * (1f - guidanceStrength) + guidanceAcc * guidanceStrength;

// 5. 应用加速度
Vector3 velocityChange = totalAcc * dt;
Vector3 newVel = vel + velocityChange;

// 6. 角度限制
if (maxAngularVelocity > 0f)
{
    return LimitAngleChange(vel, newVel, maxAngularVelocity, dt);
}
```

### 2.4 Trigger 延迟机制简化

**之前**：
- 复杂的 `triggerDelayFrames` 机制
- 模拟 OnTriggerEnter 和 FixedUpdate 之间的延迟

**现在**：
- ✅ **移除 triggerDelayFrames**（设为 0）
- ✅ **简化逻辑**：进入 trigger 后立即检查是否应该应用（基于 physicsUpdateInterval）
- ✅ 根据实际日志，Unity trigger 激活非常快

## 三、修复后的执行流程

```
1. GravityEngine 阶段（FixedUpdate）
   - 计算基础引力加速度
   - 更新速度：v1 = v0 + a * dt

2. CoreDeflector 阶段（FixedUpdate）
   - 检测 trigger（考虑飞船半径补偿）
   - 如果进入 trigger 且满足更新间隔，应用效果
   - 叠加引导加速度和引力加速度

3. ShipState 阶段（FixedUpdate）
   - 速度缩放已移除

4. 更新位置（半隐式欧拉法）
   - r1 = r0 + v1 * dt

5. Update 阶段 Lerp（PlanetGravityCapture / GravityHubDeflector）
   - 基于 detectionInterval 应用
```

## 四、预期效果

1. ✅ **预测线应该更早开始偏转**（因为考虑了飞船半径）
2. ✅ **偏转半径应该更准确**（因为使用了半隐式欧拉法）
3. ✅ **CoreDeflector 效果应该正确触发**（因为移除了延迟机制）
4. ✅ **位置和速度应该与实际游戏更一致**（因为积分顺序与实际游戏一致）

## 五、测试建议

1. **检查预测线是否更早开始偏转**
   - 对比红色路径（实际）和绿色路径（预测）
   - 预测应该在实际路径之前或同时开始偏转

2. **检查偏转半径是否一致**
   - 预测的转弯半径应该与实际路径一致

3. **检查 CoreDeflector 激活时机**
   - 查看日志，确认预测中的激活距离与实际一致

4. **检查 maxAngularVelocity**
   - 如果预测线仍然是直线，检查 maxAngularVelocity 是否被设为 0

## 六、如果还是不准

如果修复后预测仍然不准确，请检查：

1. **maxAngularVelocity 是否有效**
   - 如果为 0，飞船将无法转弯
   - 检查快照中的 `maxAngularVelocity` 值

2. **飞船半径是否正确获取**
   - 查看日志中的 `[预测] 飞船半径: X.XXX`
   - 如果为默认值 0.5，可能需要手动调整

3. **triggerRadius 计算是否正确**
   - 查看日志中的 `trigger半径: X.XX`
   - 应该包含飞船半径补偿

4. **时间步长是否一致**
   - 确保 `predictionTimeStep = 0.02f`（与实际 FixedUpdate 一致）
