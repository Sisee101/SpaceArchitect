# 双重速度缩放问题修复说明

## 一、问题根源

### 1.1 双重速度缩放

**实际游戏流程**：
1. `ShipState.Launch(initialVelocity)` → 传入**未缩放**的速度
2. `EventManager.TriggerShipLaunched(initialVelocity)` → 触发事件，传入**未缩放**的速度
3. `ShipState.FixedUpdate()` → 在**每一帧**中应用速度缩放：`scaledVelocity = currentVelocity * speedMultiplier`

**预测流程（修复前）**：
1. `SetPreviewTrajectory(launchVelocity)` → 应用速度缩放：`effectiveVelocity = launchVelocity * speedMultiplier`（**第一次缩放**）
2. `PredictFullTrajectory(startVel)` → 在**每一步**中应用速度缩放：`currentVel *= speedMultiplier`（**第二次缩放**）
3. **结果**：速度被缩放了 `speedMultiplier^2` 倍！

### 1.2 影响

- 如果 `speedMultiplier = 1.001`，预测速度会被缩放到 `1.001^2 = 1.002001` 倍
- 这会导致预测轨迹与实际轨迹有显著差异
- 累积误差会随着时间增长而放大

## 二、修复方案

### 2.1 修复 `SetPreviewTrajectory`

**修复前**：
```csharp
effectiveVelocity = launchVelocity * speedMultiplier; // 第一次缩放
cachedPreviewTrajectory = SimulateTrajectory(launchPosition, effectiveVelocity);
```

**修复后**：
```csharp
// 直接使用传入的原始速度（未缩放）
cachedPreviewTrajectory = SimulateTrajectory(launchPosition, launchVelocity);
```

**原因**：
- 实际游戏中，速度缩放是在 `FixedUpdate` 中每一步应用的，不是在初始速度中应用的
- 如果在这里应用缩放，然后在 `PredictFullTrajectory` 中又应用缩放，会导致双重缩放

### 2.2 确保 `PredictFullTrajectory` 中的速度缩放正确

**修复前**：
- `SetPreviewTrajectory` 中应用了一次缩放
- `PredictFullTrajectory` 中每一步又应用了一次缩放
- 导致双重缩放

**修复后**：
- `SetPreviewTrajectory` 中**不应用**缩放（使用原始速度）
- `PredictFullTrajectory` 中只在 FixedUpdate 间隔时应用一次缩放
- 与实际游戏的 `FixedUpdate` 逻辑一致

### 2.3 确保 `OnShipLaunched` 中的速度处理正确

**修复**：
- 使用传入的 `actualLaunchVelocity`（**未缩放**，与实际游戏一致）
- 速度缩放会在 `PredictFullTrajectory` 中每一步应用

## 三、修复后的流程

### 3.1 实际游戏流程

1. `ShipSimpleLauncher.LaunchShip()` → `velocity = currentLaunchDirection * launchSpeed`（未缩放）
2. `ShipState.Launch(velocity)` → 设置 `nBody.vel = velocity`（未缩放）
3. `EventManager.TriggerShipLaunched(velocity)` → 触发事件（未缩放）
4. `ShipState.FixedUpdate()` → 在**每一帧**中应用缩放：`scaledVelocity = currentVelocity * speedMultiplier`

### 3.2 预测流程（修复后）

1. `OnShipLaunched(actualLaunchVelocity)` → 接收**未缩放**的速度
2. `SetPreviewTrajectory(launchPosition, actualLaunchVelocity)` → 使用**未缩放**的速度
3. `PredictFullTrajectory(startVel)` → 在 FixedUpdate 间隔时应用缩放：`currentVel *= speedMultiplier`（**只应用一次**）

## 四、预期效果

修复后：
1. **初始速度一致**：预测和实际使用相同的初始速度（未缩放）
2. **速度缩放一致**：预测和实际在相同的时机应用速度缩放（每一步）
3. **效果一致**：预测的轨迹应该与实际轨迹高度一致

## 五、验证方法

1. 运行游戏并发射飞船
2. 检查控制台日志，确认：
   - `SetPreviewTrajectory` 使用的是未缩放的速度
   - `PredictFullTrajectory` 中只在 FixedUpdate 间隔时应用一次缩放
3. 对比 `FlightDataLog.txt` 和 `PredictionDataLog.txt`，确认：
   - 初始速度完全一致
   - 速度变化趋势一致
   - 轨迹高度一致
