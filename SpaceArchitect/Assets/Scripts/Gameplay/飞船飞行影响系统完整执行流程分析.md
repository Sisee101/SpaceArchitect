# 飞船飞行影响系统完整执行流程分析

## 一、Unity 生命周期执行顺序

### 每帧执行顺序（关键！）

```
1. GravityEngine.FixedUpdate()
   └─> PhysicsLoop()
       └─> EvolveByTimestep()
           └─> worldState.Evolve()
               └─> 计算所有 NBody 之间的引力（包括 Core 的 NBody 引力）
               └─> 更新所有物体的位置和速度（基于引力计算）

2. CoreDeflector.FixedUpdate()
   └─> 读取速度：gravityEngine.GetVelocity() ← 这是 GravityEngine 刚计算好的速度
   └─> 应用 CoreDeflector 的引力加速度和引导加速度
   └─> 修改速度：gravityEngine.SetVelocity() ← 覆盖 GravityEngine 的结果

3. ShipState.FixedUpdate()
   └─> 读取速度：gravityEngine.GetVelocity() ← 这是经过 CoreDeflector 处理后的速度
   └─> 应用速度缩放：velocity * speedMultiplier
   └─> 修改速度：gravityEngine.SetVelocity() ← 覆盖之前的结果

4. PlanetGravityCapture.Update()
   └─> 读取速度：ge.GetVelocity() ← 这是经过所有 FixedUpdate 处理后的速度
   └─> 应用轨道引导（Lerp 调整）
   └─> 修改速度：ge.SetVelocity() ← 覆盖之前的结果

5. GravityHubDeflector.Update()
   └─> 读取速度：ge.GetVelocity() ← 这是经过所有 FixedUpdate 和 PlanetGravityCapture 处理后的速度
   └─> 应用偏转（Lerp 调整）
   └─> 修改速度：ge.SetVelocity() ← 覆盖之前的结果
```

## 二、关键发现：速度是**累积覆盖**的，不是叠加的

### 重要理解：

1. **GravityEngine** 在 FixedUpdate 中计算基础引力，更新速度
2. **CoreDeflector** 在 FixedUpdate 中读取速度，**完全重新计算**，然后覆盖
3. **ShipState** 在 FixedUpdate 中读取速度，应用缩放，然后覆盖
4. **PlanetGravityCapture** 在 Update 中读取速度，Lerp 调整，然后覆盖
5. **GravityHubDeflector** 在 Update 中读取速度，Lerp 调整，然后覆盖

### 关键问题：CoreDeflector 和 Core 的 NBody 引力关系

**发现：**
- Core 本身有 NBody 组件，会产生引力（通过 GravityEngine）
- CoreDeflector 使用自己的 `coreEffectiveMass` 计算引力
- **问题**：这两个引力是叠加还是替代？

**分析 CoreDeflector 代码：**
```csharp
// CoreDeflector 在 FixedUpdate 中：
// 1. 获取当前速度（这是 GravityEngine 已经计算好的，包括 Core 的 NBody 引力）
Vector3 shipVelocity = gravityEngine.GetVelocity(shipNBody);

// 2. 计算自己的引力加速度
float gravitationalAcceleration = coreEffectiveMass / (distance * distance);
Vector3 radialGravity = -radialDirection * gravitationalAcceleration;

// 3. 计算引导加速度
Vector3 guidanceAcceleration = ...;

// 4. 混合引力和引导
Vector3 totalAcceleration = radialGravity * (1f - guidanceStrength) + guidanceAcceleration * guidanceStrength;

// 5. 应用加速度
Vector3 velocityChange = totalAcceleration * deltaTime;
Vector3 newVelocity = shipVelocity + velocityChange;  // ← 注意：是加上 velocityChange

// 6. 覆盖速度
gravityEngine.SetVelocity(shipNBody, newVelocity);
```

**结论：**
- CoreDeflector **在 GravityEngine 计算的基础上**，**叠加**自己的引力加速度
- 所以：**Core 的 NBody 引力 + CoreDeflector 的引力 = 叠加效果**
- 但是，CoreDeflector 的引力是**增量**，不是替换

## 三、完整的执行流程（详细）

### FixedUpdate 阶段（物理计算）

```
时间：t = 0

1. GravityEngine.FixedUpdate()
   - 计算所有 NBody 之间的引力
   - 包括：Core 的 NBody 引力、Planet 的 NBody 引力
   - 更新飞船速度：v1 = v0 + a_gravity * dt
   - 内部状态：velocity = v1

2. CoreDeflector.FixedUpdate()（如果飞船在 trigger 内）
   - 读取：v_current = GetVelocity() = v1
   - 计算：a_core = coreEffectiveMass / r²
   - 计算：a_guidance = ...
   - 计算：a_total = a_core * (1 - guidanceStrength) + a_guidance * guidanceStrength
   - 更新：v2 = v1 + a_total * dt
   - 覆盖：SetVelocity(v2)

3. ShipState.FixedUpdate()
   - 读取：v_current = GetVelocity() = v2
   - 应用缩放：v3 = v2 * speedMultiplier
   - 覆盖：SetVelocity(v3)
```

### Update 阶段（引导调整）

```
4. PlanetGravityCapture.Update()（如果飞船在捕获范围内）
   - 读取：v_current = GetVelocity() = v3
   - 计算理想轨道速度：v_ideal = sqrt(M/r) * tangent
   - Lerp 调整：v4 = Lerp(v3, v_ideal, orbitGuidanceStrength)
   - 覆盖：SetVelocity(v4)

5. GravityHubDeflector.Update()（如果飞船在偏转范围内）
   - 读取：v_current = GetVelocity() = v4
   - 计算理想切向速度：v_ideal = tangent * |v4|
   - Lerp 调整：v5 = Lerp(v4, v_ideal, deflectionStrength)
   - 覆盖：SetVelocity(v5)
```

## 四、关键问题：Core 的 NBody 引力和 CoreDeflector 引力的关系

### 问题分析：

1. **Core 的 NBody 引力**：
   - 通过 GravityEngine 计算
   - 公式：`a = (mass * massScale * physToWorldFactor³) / r²`
   - 在 GravityEngine.FixedUpdate() 中应用

2. **CoreDeflector 的引力**：
   - 使用 `coreEffectiveMass`（不应用 massScale）
   - 公式：`a = coreEffectiveMass / r²`
   - 在 CoreDeflector.FixedUpdate() 中**叠加**到 GravityEngine 的结果上

### 结论：

**Core 的 NBody 引力和 CoreDeflector 的引力是叠加的！**

- GravityEngine 先计算 Core 的 NBody 引力，更新速度
- CoreDeflector 然后读取这个速度，**加上**自己的引力加速度
- 所以总引力 = Core NBody 引力 + CoreDeflector 引力

### 在预测中的处理：

**当前代码的问题：**
```csharp
// 在 CalculateGravityAcceleration 中：
CoreDeflector coreDeflector = source.GetComponent<CoreDeflector>();
if (coreDeflector != null && isInCoreDeflectorRange)
{
    // CoreDeflector 会处理这个引力，跳过 GravityEngine 的引力
    continue;  // ← 这是错误的！
}
```

**正确的处理应该是：**
```csharp
// Core 的 NBody 引力应该始终计算（通过 GravityEngine）
// CoreDeflector 的引力应该叠加（在 ApplyCoreDeflectorEffects 中）
// 不应该跳过 Core 的 NBody 引力！
```

## 五、正确的执行顺序（预测中应该模拟的）

```
每步预测（dt = predictionTimeStep）：

1. 计算基础引力（GravityEngine）
   - 包括所有 NBody 的引力（包括 Core 的 NBody 引力）
   - v = v + a_gravity * dt

2. 应用 CoreDeflector 效果（FixedUpdate 频率）
   - 读取当前速度
   - 计算 CoreDeflector 的引力加速度（叠加）
   - 计算引导加速度
   - v = v + a_coreDeflector * dt

3. 应用速度缩放（FixedUpdate 频率）
   - v = v * speedMultiplier

4. 应用 PlanetGravityCapture 效果（Update 频率）
   - v = Lerp(v, v_ideal, strength)

5. 应用 GravityHubDeflector 效果（Update 频率）
   - v = Lerp(v, v_ideal, strength)
```

## 七、总结

### 执行顺序（优先级）：
1. **GravityEngine 基础引力**（FixedUpdate）- 最高优先级，所有 NBody 引力
2. **CoreDeflector 引力叠加**（FixedUpdate）- 在 GravityEngine 基础上叠加
3. **ShipState 速度缩放**（FixedUpdate）- 在所有引力计算后缩放
4. **PlanetGravityCapture 引导**（Update）- Lerp 调整
5. **GravityHubDeflector 偏转**（Update）- Lerp 调整

### 关键理解：
- **不是取舍关系**，是**累积覆盖**关系
- **不是层级高低**，是**执行顺序**
- **Core 的 NBody 引力和 CoreDeflector 引力是叠加的**，不是替代的
