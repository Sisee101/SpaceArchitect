# 预测问题根本原因分析

## 一、日志对比发现的问题

### 1.1 时间步长不一致（严重）

**实际日志**：
- 时间步长：0.02 秒
- 第46帧：t=19.0731，CoreDeflector 激活

**预测日志**：
- 时间步长：**0.01 秒**（错误！）
- 第105步：t=1.0500，CoreDeflector 激活

**问题**：虽然代码中 `predictionTimeStep = 0.02f`，但日志显示是 0.01 秒。说明：
1. 要么代码没有重新编译
2. 要么 `PredictFullTrajectory` 传入的 `dt` 参数不是 `predictionTimeStep`

### 1.2 CoreDeflector 激活时机差异

**实际**：
- 第46帧，t=19.0731（从游戏开始），实际发射后约 1.18 秒
- 位置：(-27.478, -0.498)
- 距离：8.26
- velChange: 0.604, accel: 30.214

**预测**：
- 第105步，t=1.0500（从预测开始）
- 位置：(-29.752, -0.661)
- 距离：10.50
- velChange: 0.848, accel: 42.394

**差异**：
- 预测激活太早（1.05秒 vs 1.18秒）
- 位置偏差约 2.3 单位
- 距离差异（10.50 vs 8.26）
- 效果强度差异（velChange 和 accel 都更大）

### 1.3 位置和速度累积误差

从初始状态到 CoreDeflector 激活：
- **实际**：约 46 帧 × 0.02 秒 = 0.92 秒
- **预测**：105 步 × 0.01 秒 = 1.05 秒

但预测的位置已经偏差了约 2.3 单位，说明每一步都有误差累积。

## 二、根本原因

### 2.1 时间步长问题

**代码中**：
```csharp
[SerializeField] private float predictionTimeStep = 0.02f;
```

**但 `SimulateTrajectory` 调用**：
```csharp
return PredictFullTrajectory(startPosition, startVelocity, predictionSteps, predictionTimeStep);
```

**日志记录**：
```csharp
predictionLogBuffer.AppendLine($"预测时间步长: {dt} 秒");
```

如果 `dt` 参数传入的是 0.01，说明 `SimulateTrajectory` 或 `PredictFullTrajectory` 被其他地方调用时传入了错误的值。

### 2.2 积分方法问题

**当前使用**：LeapFrog 积分

但实际游戏中，GravityEngine 可能使用不同的积分方法。需要确认：
- GravityEngine 实际使用的积分方法
- 每一步的更新顺序是否一致

### 2.3 CoreDeflector 触发检测问题

**预测中**：
- 使用 AABB 检测 + 距离检测
- trigger 半径：10.56（50% 安全边距）

**实际中**：
- Unity 的 trigger 检测
- 实际激活距离：8.26

**问题**：
- trigger 半径计算可能不准确
- 或者 Unity 的 trigger 检测逻辑与我们的模拟不一致

## 三、修复方案

### 3.1 立即修复：确保时间步长一致

1. **检查 `SimulateTrajectory` 调用**：
   - 确保传入的 `dt` 是 `predictionTimeStep`（0.02f）
   - 不是硬编码的 0.01f

2. **检查日志记录**：
   - 确保记录的是实际使用的 `dt`，而不是字段值

### 3.2 修复 CoreDeflector 触发检测

1. **减小安全边距**：
   - 从 50% 减小到 10-20%
   - 或者根据实际日志调整

2. **改进触发检测逻辑**：
   - 完全模拟 Unity 的 trigger 检测
   - 考虑 Collider 的实际形状和旋转

### 3.3 验证积分方法

1. **确认 GravityEngine 的积分方法**：
   - 检查 `GravityEngine` 使用的积分器
   - 确保预测使用相同的积分方法

2. **验证更新顺序**：
   - 确保预测中的更新顺序与实际游戏完全一致

## 四、建议

**当前问题太多，建议**：
1. **先修复时间步长**（最基础的问题）
2. **然后修复 trigger 检测**（影响激活时机）
3. **最后优化积分方法**（影响累积误差）

**如果还是不行**：
- 考虑使用 GravityEngine 的内置预测系统
- 或者完全重写预测逻辑，从零开始
