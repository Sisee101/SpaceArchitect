# ShipTrajectoryPreviewSkill 和 TrajectoryPredictor 的区别

## 一、职责划分

### 1.1 ShipTrajectoryPreviewSkill.cs（用户交互层）

**职责**：
- ✅ **处理用户输入**（按Y键显示预览）
- ✅ **获取发射速度**（从发射器或鼠标位置）
- ✅ **调用 TrajectoryPredictor 的方法**
- ❌ **不进行任何物理计算**
- ❌ **不绘制轨迹线**

**关键代码**：
```csharp
// 第253行：只是调用，不计算
trajectoryPredictor.SetPreviewTrajectory(launchPosition, launchVelocity);

// 第256行：只是设置可见性，不绘制
trajectoryPredictor.SetTrajectoryVisible(true);
```

**作用**：
- 相当于一个"控制器"或"技能脚本"
- 负责用户交互和参数传递
- 不包含任何预测逻辑

### 1.2 TrajectoryPredictor.cs（核心计算层）

**职责**：
- ✅ **进行所有物理计算**（`PredictFullTrajectory()` 方法）
- ✅ **计算引力、CoreDeflector 效果等**
- ✅ **生成预测点**
- ✅ **绘制轨迹线**（通过 LineRenderer）
- ✅ **记录预测日志**

**关键代码**：

## 三、为什么一直修改 TrajectoryPredictor.cs

### 3.1 原因

**所有预测逻辑都在 `TrajectoryPredictor.cs` 中**：
- `PredictFullTrajectory()` - 700+行核心预测代码
- `ApplyCoreDeflector()` - CoreDeflector 效果计算
- `CalculateGravityAcceleration()` - 引力计算
- `LimitAngleChange()` - 角度限制
- 所有积分方法、trigger 检测等

**`ShipTrajectoryPreviewSkill.cs` 只是调用者**：
- 它只调用 `SetPreviewTrajectory()`
- 它不包含任何计算逻辑
- 修改它不会影响预测准确性

### 3.2 类比

**ShipTrajectoryPreviewSkill** = **遥控器**
- 按按钮（Y键）
- 发送指令（调用方法）
- 不执行实际工作

**TrajectoryPredictor** = **电视机**
- 接收指令
- 执行所有实际工作（计算、显示）
- 包含所有核心逻辑

## 四、如果预测不准，应该修改哪个？

### 4.1 预测逻辑问题 → 修改 TrajectoryPredictor.cs

**例如**：
- 时间步长不对 → 修改 `predictionTimeStep`
- CoreDeflector 效果不对 → 修改 `ApplyCoreDeflector()`
- 积分方法不对 → 修改 `PredictFullTrajectory()`
- trigger 检测不对 → 修改 `IsInTriggerBounds()`

### 4.2 用户交互问题 → 修改 ShipTrajectoryPreviewSkill.cs

**例如**：
- 按键不对 → 修改 `previewKey`
- 获取速度不对 → 修改 `GetLaunchVelocity()`
- 显示时机不对 → 修改 `Update()` 中的逻辑

## 五、当前问题分析

### 5.1 预测不准确的原因

**问题在 `TrajectoryPredictor.cs` 中**：
1. 时间步长不一致（已修复：0.01 → 0.02）
2. CoreDeflector 效果计算不准确
3. trigger 检测不准确
4. 积分方法可能不完全一致

**不在 `ShipTrajectoryPreviewSkill.cs` 中**：
- 它只是传递速度参数
- 不进行任何计算

### 5.2 为什么用户可能认为 ShipTrajectoryPreviewSkill 在计算

**可能的原因**：
1. 它调用了 `SetPreviewTrajectory()`，看起来像在"设置预测"
2. 它调用了 `SetTrajectoryVisible(true)`，看起来像在"显示轨迹"
3. 但实际上，这些只是"调用"，真正的计算在 `TrajectoryPredictor` 中

## 六、总结

| 脚本 | 职责 | 是否包含计算逻辑 | 是否绘制轨迹 |
|------|------|----------------|-------------|
| **ShipTrajectoryPreviewSkill** | 用户交互、参数传递 | ❌ 否 | ❌ 否 |
| **TrajectoryPredictor** | 物理计算、绘制轨迹 | ✅ 是 | ✅ 是 |

**结论**：
- ✅ **预测不准确的问题在 `TrajectoryPredictor.cs`**
- ✅ **所以一直修改 `TrajectoryPredictor.cs` 是正确的**
- ❌ **修改 `ShipTrajectoryPreviewSkill.cs` 不会解决预测准确性问题**

**如果预测不准，应该**：
1. 检查 `TrajectoryPredictor.PredictFullTrajectory()` 中的计算逻辑
2. 检查 `TrajectoryPredictor.ApplyCoreDeflector()` 中的效果计算
3. 检查时间步长、积分方法等参数

**不应该**：
- 修改 `ShipTrajectoryPreviewSkill.cs` 来"修复预测"（它不进行计算）
