# 飞船飞行影响系统判定机制说明

## 三种情况的判定逻辑

### 情况1：靠近 Core（CoreDeflector 生效）

#### 判定方式
- **实际游戏**：使用 Unity 的 Trigger Collider 系统
  - `OnTriggerEnter`：飞船的 Collider 进入 Core 的 Trigger Collider
  - `OnTriggerStay`：飞船保持在 Trigger 范围内
  - `OnTriggerExit`：飞船离开 Trigger 范围

- **预测系统**：模拟 Trigger 检测
  - **优先使用 AABB 检测**：检查飞船位置是否在 Core 的 Trigger bounds 内
    ```csharp
    inTrigger = IsInTriggerBounds(currentPos, source.triggerBounds);
    // 检查：point.x/y/z 是否在 bounds.min 和 bounds.max 之间
    ```
  - **备用距离检测**：如果 AABB 检测失败，使用距离检测
    ```csharp
    inTrigger = distToCore <= triggerRadius;
    // triggerRadius 已包含飞船半径补偿
    ```

#### 判定条件
- 飞船位置在 Core 的 **Trigger Collider bounds** 内
- 或者：飞船到 Core 的距离 <= **triggerRadius**（已包含飞船半径补偿）

#### 执行时机
- 在 `FixedUpdate` 中，按 `physicsUpdateInterval` 间隔执行
- 执行顺序：**步骤2**（在基础引力之后，位置更新之前）

---

### 情况2：靠近 Planet（PlanetGravityCapture 生效）

#### 判定方式
- **实际游戏**：在 `FixedUpdate` 中通过距离检测
  - `DetectNearbySpaceships()`：每 `detectionInterval` 秒检测一次
  - 使用 `Vector2.Distance` 计算距离

- **预测系统**：使用距离检测
  ```csharp
  float distance = Vector3.Distance(pos, capture.planetPosition);
  return distance <= capture.captureRadius && distance <= capture.releaseRadius;
  ```

#### 判定条件
- 飞船到 Planet 的距离 <= **captureRadius**（进入捕获范围）
- 且距离 <= **releaseRadius**（未离开释放范围）

#### 执行时机
- 在 `FixedUpdate` 中，按 `detectionInterval` 间隔执行（默认 0.1 秒）
- 执行顺序：**步骤4**（在位置更新之后，最后执行）

---

### 情况3：Core 和 Planet 区域叠加（新逻辑：CoreDeflector 优先）

#### 判定方式
- **两个系统独立判定**，但**有优先级关系**
  - CoreDeflector：检查是否在 Trigger 范围内
  - PlanetGravityCapture：检查是否在 captureRadius 内
  - **可以同时满足两个条件**

#### 执行顺序（决定优先级）

```
步骤1：基础引力（NBody）
  ↓
步骤2：CoreDeflector 叠加（如果 inTrigger = true）
  │   └─ 如果生效，设置标志：isInAnyCoreDeflectorTrigger = true
  ↓
步骤3：更新位置
  ↓
步骤4：PlanetGravityCapture 覆盖（如果 inCaptureRange = true）
  │   └─ 检查标志：如果 isInAnyCoreDeflectorTrigger = true，则跳过
```

#### 优先级说明（新逻辑）

**核心规则**：**如果飞船在 CoreDeflector 的 trigger 范围内，PlanetGravityCapture 会被跳过**

1. **CoreDeflector 先执行**（步骤2）
   - 使用**叠加操作**：`newVelocity = oldVelocity + velocityChange`
   - 在基础引力速度上叠加效果
   - **如果生效，设置标志**：`isInAnyCoreDeflectorTrigger = true`

2. **PlanetGravityCapture 后执行**（步骤4）
   - **先检查标志**：如果 `isInAnyCoreDeflectorTrigger = true`，**跳过**（不应用）
   - 如果 `isInAnyCoreDeflectorTrigger = false`，才应用覆盖操作
   - 使用**覆盖操作**：`newVelocity = Lerp(currentVelocity, idealVelocity, strength)`

#### 实际效果（区域叠加情况）

**情况 3.1：飞船在叠加区域内**（既在 Core trigger 内，也在 Planet captureRadius 内）
- ✅ **CoreDeflector 生效**（步骤2，叠加效果）
- ❌ **PlanetGravityCapture 被跳过**（步骤4，因为 `isInAnyCoreDeflectorTrigger = true`）
- **最终效果**：只有 CoreDeflector 的弹弓偏转效果

**情况 3.2：飞船只在 Planet 区域内**（不在 Core trigger 内，但在 Planet captureRadius 内）
- ❌ CoreDeflector 不生效（不在 trigger 范围内）
- ✅ **PlanetGravityCapture 生效**（步骤4，覆盖效果）
- **最终效果**：PlanetGravityCapture 的轨道引导效果

**情况 3.3：飞船只在 Core 区域内**（在 Core trigger 内，但不在 Planet captureRadius 内）
- ✅ **CoreDeflector 生效**（步骤2，叠加效果）
- ❌ PlanetGravityCapture 不生效（不在 captureRadius 内）
- **最终效果**：只有 CoreDeflector 的弹弓偏转效果

#### 设计意图
- **CoreDeflector 优先**：在叠加区域内，CoreDeflector 的弹弓偏转效果优先于 PlanetGravityCapture 的轨道引导
- **避免冲突**：防止两个系统同时作用导致轨迹不稳定
- **保留原逻辑**：如果不在 Core trigger 范围内，PlanetGravityCapture 正常生效

#### 区域叠加示意图

```
         Planet 捕获范围 (captureRadius)
        ┌─────────────────────────────┐
        │                             │
        │    Core Trigger 范围        │
        │    ┌─────────────┐          │
        │    │             │          │
        │    │    Core     │          │
        │    │             │          │
        │    └─────────────┘          │
        │                             │
        │         Planet              │
        └─────────────────────────────┘

区域说明：
1. 叠加区域（Core Trigger + Planet Capture）：
   ✅ CoreDeflector 生效
   ❌ PlanetGravityCapture 被跳过

2. 只在 Planet 区域（Planet Capture，不在 Core Trigger）：
   ❌ CoreDeflector 不生效
   ✅ PlanetGravityCapture 生效

3. 只在 Core 区域（Core Trigger，不在 Planet Capture）：
   ✅ CoreDeflector 生效
   ❌ PlanetGravityCapture 不生效
```

## 判定流程图

```
每帧 FixedUpdate：
  │
  ├─ 步骤1：计算基础引力（NBody）
  │   └─ 所有有质量的物体都参与
  │
  ├─ 步骤2：检查 CoreDeflector
  │   ├─ 判定：飞船是否在 Core 的 Trigger 范围内？
  │   │   ├─ 是 → 应用 CoreDeflector 叠加效果
  │   │   └─ 否 → 跳过
  │   └─ 作用方式：叠加（增量）
  │
  ├─ 步骤3：更新位置
  │
  └─ 步骤4：检查 PlanetGravityCapture
      ├─ 判定：飞船是否在 Planet 的 captureRadius 内？
      │   ├─ 是 → 检查是否在 CoreDeflector trigger 范围内？
      │   │   ├─ 是（isInAnyCoreDeflectorTrigger = true）→ 跳过 PlanetGravityCapture
      │   │   └─ 否（isInAnyCoreDeflectorTrigger = false）→ 应用 PlanetGravityCapture 覆盖效果
      │   └─ 否 → 跳过
      └─ 作用方式：覆盖（Lerp）
```

---

## 关键区别

| 系统 | 判定方式 | 判定条件 | 执行顺序 | 作用方式 |
|------|---------|---------|---------|---------|
| **CoreDeflector** | Trigger Collider 或距离 | 在 Trigger bounds 内 或 距离 <= triggerRadius | 步骤2（较早） | 叠加（增量） |
| **PlanetGravityCapture** | 距离检测 | 距离 <= captureRadius 且 <= releaseRadius | 步骤4（较晚） | 覆盖（Lerp） |

## 总结

1. **判定是独立的**：两个系统各自判定，互不影响
2. **优先级规则（新逻辑）**：
   - 如果飞船在 **CoreDeflector trigger 范围内**，PlanetGravityCapture **会被跳过**
   - 如果飞船不在 CoreDeflector trigger 范围内，PlanetGravityCapture **正常生效**
3. **区域叠加时的效果**：
   - **叠加区域内**：只有 CoreDeflector 生效（弹弓偏转）
   - **只在 Planet 区域内**：只有 PlanetGravityCapture 生效（轨道引导）
   - **只在 Core 区域内**：只有 CoreDeflector 生效（弹弓偏转）
4. **设计意图**：CoreDeflector 优先，避免两个系统同时作用导致轨迹不稳定
