# 预测逻辑修复说明

## 一、问题分析

### 1.1 为什么不能使用 GravityEngine 内置预测？

**用户说得对！** GravityEngine 的内置轨迹预测**不会处理自定义组件**：

- ❌ **CoreDeflector** - 自定义的 trigger 效果（不是 NBody 引力）
- ❌ **PlanetGravityCapture** - 自定义的捕获逻辑
- ❌ **GravityHubDeflector** - 自定义的偏转逻辑
- ❌ **ShipState** - 速度缩放（虽然已移除）

这些组件都是**自定义脚本**，GravityEngine 的内置预测系统**不知道它们的存在**。

### 1.2 当前预测代码的问题

**之前的"简化版本"（第905-936行）**：
- 移除了所有延迟机制
- 进入 trigger 后立即应用效果
- **但实际游戏中，OnTriggerEnter 和 FixedUpdate 应用效果之间有延迟！**

## 二、实际游戏的执行流程

### 2.1 CoreDeflector 的执行流程

```
1. 飞船进入 trigger
   ↓
2. OnTriggerEnter 调用
   - 将飞船添加到 shipsInTrigger 字典
   - 记录当前 fixedUpdateCounter（进入时的帧数）
   ↓
3. FixedUpdate 调用（每 0.02 秒）
   - 检查 shipsInTrigger 中的飞船
   - 计算 framesSinceLastUpdate = fixedUpdateCounter - lastUpdateFrame
   - 如果 framesSinceLastUpdate >= updateIntervalFrames，应用效果
   - 应用效果后，更新 shipsInTrigger[shipRoot] = fixedUpdateCounter
```

### 2.2 关键点

1. **OnTriggerEnter 可能在 FixedUpdate 之间调用**
   - Unity 的 trigger 检测是异步的
   - 可能在 FixedUpdate 之间触发

2. **第一次应用效果的时机**
   - `OnTriggerEnter` 记录的是**进入时的帧数**
   - `FixedUpdate` 检查的是**距离上次更新的帧数**
   - 第一次应用时，`lastUpdateFrame` 是进入时的帧数
   - 所以 `framesSinceLastUpdate` 可能很小（甚至为0）
   - 但实际应用中，可能在**下一个 FixedUpdate** 才应用

3. **更新间隔检查**
   - `updateIntervalFrames = physicsUpdateInterval / fixedUnscaledDeltaTime`
   - 如果 `physicsUpdateInterval = 0.02`，`fixedUnscaledDeltaTime = 0.02`，则 `updateIntervalFrames = 1`
   - 这意味着**每个 FixedUpdate 都应用**（如果满足条件）

## 三、修复后的预测逻辑

### 3.1 完全模拟实际游戏流程

```csharp
// 1. 检测 trigger 状态变化（模拟 OnTriggerEnter/OnTriggerExit）
if (inTrigger && !wasInTrigger)
{
    // 模拟 OnTriggerEnter：记录进入时的"帧数"（预测中的步数）
    deflectorEntered[idx] = true;
    deflectorEnterStep[idx] = i;
    deflectorLastUpdateStep[idx] = -1; // 初始未应用
}

// 2. 模拟 FixedUpdate：检查是否应该应用效果
if (deflectorEntered.ContainsKey(idx) && deflectorEntered[idx])
{
    // 计算距离上次应用的步数
    int lastUpdateStep = deflectorLastUpdateStep.ContainsKey(idx) ? deflectorLastUpdateStep[idx] : -1;
    int stepsSinceLastUpdate = (lastUpdateStep < 0) ? stepsSinceEnter : (i - lastUpdateStep);
    
    // 检查是否满足更新间隔（与实际游戏一致）
    if (lastUpdateStep < 0 || stepsSinceLastUpdate >= deflectorUpdateInterval)
    {
        // 应用效果
        currentVel = ApplyCoreDeflector(currentPos, currentVel, source.deflector, fixedUnscaledDeltaTime);
        deflectorLastUpdateStep[idx] = i; // 更新上次应用的步数
    }
}
```

### 3.2 关键修复点

1. **保留延迟机制**
   - 不再"立即应用"
   - 完全模拟 `OnTriggerEnter` → `FixedUpdate` 的流程

2. **帧计数器检查**
   - 使用 `stepsSinceLastUpdate` 检查更新间隔
   - 与实际游戏的 `framesSinceLastUpdate` 逻辑一致

3. **第一次应用时机**
   - `lastUpdateStep < 0` 时，表示第一次应用
   - 使用 `stepsSinceEnter` 作为初始值
   - 确保第一次应用在**进入后的第一个满足间隔的 FixedUpdate**
