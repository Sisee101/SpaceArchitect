# 动画不播放问题排查指南

## 问题描述
点击按钮能够完成任务，但是返回 MainHub 场景后不播放任务完成动画。

## 系统工作原理

### 正常流程
1. **游戏场景**：点击按钮 → `OrderCompleteAndLoadSceneButton` 处理
   - 设置 `orderInfo.CompleteOrder = true`
   - 将 `taskId` 添加到静态变量 `pendingCompletedTaskIds`
   - 调用 `TaskManager.CompleteTask(taskId)` 持久化任务状态
   - 卸载游戏场景，返回 MainHub

2. **MainHub 场景**：场景加载完成 → `TaskCompletionHandler.Start()` 执行
   - 检查 `OrderCompleteAndLoadSceneButton.IsPendingForAnimation(taskId)`
   - 如果任务在待播放列表中 → 播放动画序列
   - 播放顺序：显示胜利图片+印章 → 图片消失 → 气泡消失动画

## 使用诊断工具

### 步骤 1：添加诊断脚本
1. 打开 `01_MainHub` 场景
2. 在 Hierarchy 中创建空 GameObject，命名为 `AnimationDebugHelper`
3. 添加 `AnimationDebugHelper` 组件
4. 在 Inspector 中配置：
   - **Order Data Config**：拖拽 `SphereOrderDataConfig` 资源
   - **Task Completion Handler**：留空（会自动查找）
   - **Auto Check On Start**：勾选
   - **Enable Debug Log**：确保勾选

### 步骤 2：运行诊断
1. 保存场景
2. 运行游戏
3. 进入 MainHub 场景
4. 查看 Console 输出的诊断信息

### 步骤 3：手动触发诊断
- 在 Inspector 中右键 `AnimationDebugHelper` 组件
- 选择 **执行完整诊断**
- 查看 Console 输出

## 常见问题和解决方案

### 问题 1：静态变量为空或未包含任务
**症状**：诊断显示 `pendingCompletedTaskIds 包含 0 个任务ID`

**可能原因**：
1. **场景切换时序问题**
   - `TaskCompletionHandler.Start()` 执行得太快，在按钮添加任务到列表之前就检查了
   - **解决方案**：在 `TaskCompletionHandler` 中延迟检查

2. **按钮脚本未正确执行**
   - 按钮点击时没有成功添加到静态列表
   - **解决方案**：检查 `OrderCompleteAndLoadSceneButton` 的 `enableDebugLog`，查看是否输出了添加日志

3. **静态变量被意外清空**
   - 某个地方调用了 `ClearPendingOrders()`
   - **解决方案**：搜索代码中所有调用 `ClearPendingOrders()` 的地方

### 问题 2：TaskCompletionHandler 未配置
**症状**：诊断显示 `场景中未找到 TaskCompletionHandler`

**解决方案**：
1. 打开 `01_MainHub` 场景
2. 检查 Hierarchy 中是否有 `TaskCompletionHandler` GameObject
3. 如果没有，创建并添加组件
4. 配置所有必需的引用：
   - **Task Manager**
   - **Icon Manager**
   - **Victory Feedback Display Mono**（实现 `IVictoryFeedbackDisplay` 的组件）
   - **Order Data Config**

### 问题 3：TaskCompletionHandler 引用未配置
**症状**：诊断显示某个引用 `未配置`

**解决方案**：
1. 选中 `TaskCompletionHandler` GameObject
2. 在 Inspector 中配置缺失的引用：
   ```
   Task Manager → 拖拽场景中的 TaskManager
   Icon Manager → 拖拽场景中的 SphereIconManager
   Victory Feedback Display Mono → 拖拽实现了 IVictoryFeedbackDisplay 的组件（如 VictoryImageDisplay）
   Order Data Config → 拖拽 SphereOrderDataConfig 资源
   ```

### 问题 4：enableDebugLog 未启用
**症状**：看不到任何详细日志

**解决方案**：
1. 选中 `TaskCompletionHandler` GameObject
2. 在 Inspector 中勾选 `Enable Debug Log`
3. 同样检查 `OrderCompleteAndLoadSceneButton` 的 `Enable Debug Log`

### 问题 5：OrderDataConfig 中 CompleteOrder 状态不正确
**症状**：诊断显示订单的 `CompleteOrder` 为 `未完成`

**可能原因**：
1. **ScriptableObject 未保存**
   - 游戏运行时的修改没有保存到资源文件
   - **解决方案**：使用 `TaskManager` 的持久化系统（通过 `taskId`）

2. **使用了多个 OrderDataConfig 副本**
   - 不同场景引用了不同的配置文件
   - **解决方案**：确保所有场景使用同一个 `SphereOrderDataConfig` 资源

### 问题 6：任务已经在 globallyProcessedTaskIds 中
**症状**：诊断显示 `已播放动画的任务ID: X`

**可能原因**：
- 之前已经播放过动画，系统防止重复播放
- **解决方案**：
  1. 使用诊断工具的 **清空所有静态变量** 功能
  2. 或者重启Unity编辑器（静态变量会重置）

### 问题 7：胜利反馈未配置
**症状**：诊断显示 `未配置 orderImage 或 victoryVideoClip`

**解决方案**：
1. 打开 `SphereOrderDataConfig` 资源
2. 为每个订单配置：
   - **Order Image**（优先）或
   - **Victory Video Clip**（向后兼容）

## UIManager 改动的影响分析

### 改动内容
`UIManager` 从跨场景持久化单例改为场景级单例（随场景销毁）

### 影响评估
**理论上不应该影响动画播放**，因为：
1. `OrderCompleteAndLoadSceneButton` 的静态变量与 `UIManager` 无关
2. `TaskCompletionHandler` 也不依赖 `UIManager`

**但如果出现问题，可能是**：
- 场景卸载/加载的时序发生变化
- 某个组件在初始化顺序上发生了改变

### 验证方法
1. 临时恢复 `UIManager` 的旧版本
2. 测试动画是否恢复正常
3. 如果恢复正常，说明问题与 `UIManager` 有关

## 最可能的原因

根据经验，最常见的原因是：

### ⭐ 原因 1：TaskCompletionHandler.Start() 执行时机早于静态变量设置
**概率：40%**
- **现象**：`TaskCompletionHandler` 在场景加载时就执行 `Start()`，但此时静态变量还未设置
- **解决方案**：在 `TaskCompletionHandler.Start()` 中添加延迟，或者使用 `Update()` 持续检查

### ⭐ 原因 2：静态变量被过早清空
**概率：30%**
- **现象**：`TaskCompletionHandler` 的 `CleanupPendingOrdersAfterDelay()` 在 1 秒后清空了列表
- **解决方案**：检查这个延迟是否足够，或者调整时机

### ⭐ 原因 3：场景加载顺序问题
**概率：20%**
- **现象**：使用 Additive 模式加载场景时，MainHub 场景已经加载，`TaskCompletionHandler` 不会重新执行 `Start()`
- **解决方案**：检查场景切换方式，确保返回 MainHub 时会重新初始化

### ⭐ 原因 4：引用配置错误
**概率：10%**
- **现象**：`TaskCompletionHandler` 的某个引用为空，导致逻辑中断
- **解决方案**：使用诊断工具检查所有引用
